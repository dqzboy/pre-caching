# ===========================================================================
# 网站预缓存定时任务
#
# 安装前准备（只需一次）：
#   1. cp precache.env.example precache.env
#   2. 改 precache.env 里的 SITEMAP_URL / CACHE_HEADER
#   3. 手动跑一次确认：/bin/bash /opt/pre-caching/run_precache.sh
#   4. 安装本文件：crontab crontab_example.txt
#
# 站点参数（SITEMAP_URL / CACHE_HEADER 等）配在 precache.env 里，
# 下面只写"这一次执行特有"的差异，所以每行都很短。
# ===========================================================================

# 定时任务的运行环境。cron 不读 /etc/profile，不设的话 PATH 里可能缺 flock 等命令。
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

# ---------------------------------------------------------------------------
# 【每小时 · 增量】
# 触发时间：每小时的第 5 分钟（00:05、01:05、02:05 …… 一天 24 次）
#           用 5 而不是 0，是为了避开整点高峰
# LASTMOD=2h  只预热 sitemap 里 lastmod 在最近 2 小时内变更的页面，
#             通常只有几篇，压力最小；适合发完文章后快速回温
# 日志：追加写入 cron.log，超过 5MB 自动轮转为 cron.log.1
# ---------------------------------------------------------------------------
5 * * * * LASTMOD=2h /bin/bash /opt/pre-caching/run_precache.sh >> /opt/pre-caching/cron.log 2>&1

# ---------------------------------------------------------------------------
# 【每天 03:10 · 全量】
# 触发时间：每天凌晨 3 点 10 分
# 作用：全部页面刷一遍，兜底。增量只覆盖"最近变更"的页面，
#       缓存 TTL 到期的老页面没人访问就会一直 MISS，靠这次全量回温
# RECHECK=1m  预热完等 1 分钟再复检一次，确认页面真的进了缓存，
#             复检结果会直接打印"X 个页面中 Y 个已命中"
# JSON_OUT    把结果写成 JSON，方便接监控或对比历史
# ---------------------------------------------------------------------------
10 3 * * * RECHECK=1m JSON_OUT=/opt/pre-caching/last-report.json /bin/bash /opt/pre-caching/run_precache.sh >> /opt/pre-caching/cron.log 2>&1

# ===========================================================================
# 时间格式：分 时 日 月 周
#
#   5 * * * *     分=5，其余不限  → 每小时第 5 分钟（24 次/天）
#   */5 * * * *   分=每 5 分钟   → 每 5 分钟一次（288 次/天）
#   0 */5 * * *   时=每 5 小时   → 0/5/10/15/20 点整（约 5 次/天）
#   10 3 * * *    分=10 时=3     → 每天 03:10
#
# 注意区分：字段写 5 是"第 5 分钟"，写 */5 才是"每隔 5 分钟"。
# ===========================================================================
# 其他可选频率
#   每 6 小时：        0 */6 * * *
#   每天 8 点和 20 点： 0 8,20 * * *
#   工作日每 2 小时：   0 */2 * * 1-5
#   每周日凌晨 3 点：   0 3 * * 0
# ===========================================================================
# 常见错误写法（对照检查）
#   ✗ 0 */1* * * ...     小时字段 */1* 是非法语法，crontab 会报 bad hour
#   ✗ ... > cron.log     用 > 每次覆盖，永远只剩最后一次的日志
#   ✗ ... && echo 时间   脚本非 0 退出时不执行，恰恰失败时没有日志
#   ✗ 日志写 /tmp        /tmp 重启会清空，目录被清理时重定向失败还会导致
#                        整条命令根本不执行（cron 里完全静默）
#   ✗ 直接跑脚本不加 /bin/bash   依赖文件执行位，scp 传丢权限就 Permission denied
# ===========================================================================
# 其他
#   - 退出码：0 正常 / 1 致命错误 / 3 错误率超阈值 / 4 触发熔断 / 130 被中断
#   - 脚本自带防重叠锁，上一次没跑完会自动跳过本次，不会叠加压力
#   - 排查是否真的触发：journalctl -u cron --since today | grep CRON
# ===========================================================================
